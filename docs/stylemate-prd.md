# StyleMate 产品需求文档 PRD

## 1. 产品概述

`StyleMate` 是一个 AI 智能穿搭与个人风格顾问 Web 产品，帮助用户从“我喜欢什么风格”走到“我适合什么风格”，再走到“今天这套怎么改”。

当前产品核心由四部分组成：

1. 风格库：提供 80 种穿搭风格百科。
2. 风格测评：通过用户画像、偏好、自述和照片生成风格档案。
3. AI 风格档案：结合本地规则和 LLM 输出可执行建议。
4. 今日穿搭诊断：上传 Look 后获得 8 维评分和修改建议。

## 2. 要解决的问题

用户主要痛点：

- 不知道自己适合什么风格。
- 喜欢某种穿搭，但不知道是否适合自己的身材、预算和场景。
- 不知道一套穿搭哪里不协调、怎么修改。
- 穿搭建议太泛泛，缺少结合个人画像的可执行方案。
- 衣橱单品难以管理，后续缺少搭配推荐和缺口分析。

业务目标：

- 用风格库建立审美认知。
- 用测评建立个人风格档案。
- 用 AI 输出个性化风格建议。
- 用今日诊断形成高频使用场景。
- 后续通过衣橱和推荐形成长期管理闭环。

## 3. 目标用户

| 用户类型 | 特征 | 需求 |
|---|---|---|
| 学生用户 | 预算有限、喜欢尝试 | 找到适合自己的安全风格 |
| 初入职场用户 | 通勤/面试/社交场景多 | 得体、专业、不老气 |
| 年轻白领 | 有消费能力但缺少系统审美 | 建立稳定个人风格 |
| 穿搭新手 | 不知道怎么搭配 | 获得直接可执行建议 |
| 审美探索者 | 喜欢看图和收藏风格 | 浏览风格库寻找灵感 |
| 拍照/约会/旅行用户 | 临时需要 Look 优化 | 诊断今日穿搭并快速修改 |

## 4. 核心使用场景

### 4.1 找到适合自己的风格

用户进入 `/onboarding`，填写性别、身高、体重、年龄段、职业、城市、预算、偏好风格和自述，可选上传正脸照/全身照，系统生成 Top 8 风格匹配结果。

### 4.2 浏览风格灵感

用户进入 `/styles`，按地域文化、视觉元素、场景圈层、人物原型浏览 80 种风格，并进入详情页查看核心单品、廓形、颜色和避雷点。

### 4.3 判断今日穿搭

用户进入 `/score-outfit`，上传完整 Look，选择诊断视角，系统从比例、色彩、场景、完整度、趋势、创意、身材适配、实穿性 8 个维度评分。

### 4.4 基于个人档案进行诊断

用户完成风格测评后，风格档案保存在 `localStorage`。今日诊断时自动附带体型、身高、体重、职业、城市和风格偏好，让诊断更个性化。

## 7. 功能需求

### 7.1 首页

目标：传达产品定位，引导用户进入风格库、测评和诊断。

验收：

- 访问 `/` 能看到品牌、主文案和核心入口。
- 点击风格库跳转 `/styles`。
- 点击测评跳转 `/onboarding`。
- 点击诊断跳转 `/score-outfit`。

### 7.2 风格库

目标：让用户浏览和搜索 80 种穿搭风格。

风格字段：

- `id`
- `name`
- `dimension`
- `category`
- `description`
- `philosophy`
- `difficulty`
- `silhouette`
- `keyItems`
- `colorPalette`
- `imageUrl?`

验收：

- 展示全部风格数量。
- 支持按 4 大维度筛选。
- 支持搜索风格名、描述、分类、单品、廓形、理念。
- 无结果时展示空状态。
- 点击风格卡进入详情。

### 7.3 风格详情

目标：解释单个风格如何穿、适合谁、注意什么。

页面内容：

- 风格图。
- 风格描述。
- 维度和分类。
- 风格哲学。
- 适合谁。
- 入门难度。
- 避雷点。
- 场景建议。
- 核心单品。
- 廓形规则。
- 颜色体系。
- 开始测评 CTA。

验收：

- 正确展示对应 `id` 风格。
- 不存在 ID 返回 404。
- 可返回风格库。
- 可跳转测评。

### 7.4 风格测评

目标：收集用户画像并生成风格档案。

步骤：

1. 照片与画像。
2. 偏好选择。
3. 自述编辑器。
4. 结果页。

第一步必填：

- 性别。
- 身高。
- 体重。
- 年龄段。

可选：

- 正脸照。
- 全身照。
- 胸围/腰围/臀围。
- 职业。
- 城市。
- 气候。

第二步可选：

- 喜欢风格。
- 单件预算。
- 月度预算。
- 穿衣目标。
- 优先级。
- 风格接受度。
- 是否愿意尝试新风格。

第三步：

- 系统自动生成自述。
- 用户可编辑。
- 自述至少 20 字才能提交。

验收：

- 必填项未完成不能继续。
- 自述不足 20 字不能提交。
- 提交后先生成本地匹配结果。
- AI 成功显示 AI 深度分析。
- AI 失败显示本地规则回退。
- 结果保存到 `stylemate.styleProfile.v1`。

### 7.5 本地风格匹配

目标：AI 不可用时仍能完成测评。

总分 100：

| 一级维度 | 分数 |
|---|---:|
| 审美适配 | 50 |
| 现实约束 | 30 |
| 行为偏好 | 20 |

细分：

| 子项 | 分数 |
|---|---:|
| 体型匹配 | 20 |
| 偏好匹配 | 25 |
| 肤色匹配 | 5 |
| 预算匹配 | 12 |
| 年龄适配 | 8 |
| 场景适配 | 10 |
| 优先级匹配 | 10 |
| 穿衣目标匹配 | 5 |
| 开放度匹配 | 5 |

输出：

- Top 8 风格。
- 总分。
- 三支柱分数。
- 细分得分。
- 匹配理由。

### 7.6 AI 风格档案

目标：结合照片、自述和候选风格，输出更像真人顾问的报告。

输入：

- 用户画像。
- 本地体型。
- 用户自述。
- 本地候选风格。
- 正脸照，可选。
- 全身照，可选。

输出：

- `summary`
- `visualAnalysis.face`
- `visualAnalysis.body`
- `visualAnalysis.confidence`
- `intentAnalysis`
- `recommendedStyles`
- `avoidanceAdvice`
- `nextActions`

规则：

- 只返回 JSON。
- 不做身份识别。
- 不判断敏感属性。
- 推荐风格 ID 只能来自候选列表。
- 可以指出不适合，但必须给替代方案。

### 7.7 今日穿搭诊断

目标：上传 Look 后获得多维度诊断。

流程：

1. 上传图片。
2. 选择博主视角。
3. 调用 `/scoring/evaluate`。
4. 展示结果。

诊断维度：

- `proportion` 比例。
- `color` 色彩。
- `occasion` 场景。
- `coherence` 协调性。
- `trend` 趋势。
- `creativity` 创意。
- `bodyFit` 身材适配。
- `practicality` 实穿性。

验收：

- 未上传图片不能提交。
- 未选博主不能提交。
- 请求中展示 loading。
- 成功后展示雷达图、8 维卡片、整体评价、逐件分析、改良建议。
- 失败后展示错误并允许重试。

### 7.8 我的衣橱

当前 MVP 只保留入口和空状态。

当前验收：

- `/wardrobe` 可访问。
- 展示“我的衣橱”。
- 展示添加衣物按钮。
- 展示拍照添加、手动录入。
- 展示 6 个分类。

后续完整能力：

- 添加衣物。
- 编辑衣物。
- 删除衣物。
- 分类筛选。
- 创建搭配。
- 记录穿着次数。
- 衣橱缺口分析。

## 8. 数据与权限

### 当前 MVP

- 风格库无需登录。
- 测评无需登录。
- 今日诊断无需登录。
- 风格档案存在浏览器 `localStorage`。
- 衣橱和推荐后端已有 `userId` 设计，但缺少完整鉴权。

### 后续要求

- 登录注册。
- JWT 或 Session。
- 用户只能访问自己的衣橱和搭配。
- 服务端保存照片前必须授权。
- 图片上传限制大小和类型。
- AI 请求限频。
- 支持用户删除数据。

## 9. 非功能需求

| 类型 | 要求 |
|---|---|
| 性能 | 风格筛选/搜索 300ms 内响应 |
| AI 风格分析 | 建议 90 秒内返回 |
| AI 穿搭诊断 | 建议 60 秒内返回 |
| 可用性 | AI 失败必须回退本地结果 |
| 安全 | 不记录完整图片 base64 日志 |
| 隐私 | 不做身份识别和敏感属性判断 |
| 兼容 | 支持现代桌面和移动浏览器 |

## 10. 关键验收标准

- 首页、风格库、风格详情、测评、诊断、衣橱页面均可访问。
- 风格库可筛选、搜索、进入详情。
- 测评流程可完整走通。
- AI 成功时展示 AI 报告。
- AI 失败时展示本地规则报告。
- 风格档案可被今日诊断读取。
- 今日诊断能上传图片、选择博主并展示 8 维报告。
- 衣橱页面至少展示空状态和分类入口。

## 13. 当前建议下一步

优先做 Phase 2 中最小且高价值的改进：

1. 增加本地风格档案清除/重新生成入口。
2. 增加图片上传大小限制和错误提示。
3. 增加诊断历史本地保存。
4. 优化 AI 错误提示和重试入口。

推荐先做第 1、2 项，因为它们风险低、价值明确、对现有架构侵入小。
